# render-budget-core — Benchmark Results — 2026-07-21

First benchmark for this package — no prior baseline to compare against.

```
planBudget() — pure decision logic, no I/O: 0.05 µs/op  (100000 iterations)
profileHardware() — 16-context probe loop (fake env, no real GPU): 0.003 ms/op  (1000 iterations)
profileNetwork() — connection read path (no fallback probe): 0.000 ms/op  (10000 iterations)
initRenderBudget() end-to-end, cold cache: 0.005 ms/op  (1000 iterations)
initRenderBudget() end-to-end, warm hardware cache: 0.003 ms/op  (1000 iterations)
```

## Notes

- `planBudget()` is pure arithmetic (tier ranking, min comparison) — sub-microsecond, as expected for a function with no I/O and no allocation beyond one small object.
- `profileHardware()`'s benchmark number reflects only this package's own loop/overhead — it's measured against a fake env with no real GPU calls. The real-world cost is dominated entirely by actual `canvas.getContext('webgl2')` / context-loss calls on real hardware, which this package doesn't control and which this benchmark can't and shouldn't attempt to characterize (that number belongs to a real-device profiling pass, not a unit benchmark).
- Cold vs. warm cache for `initRenderBudget()` shows the expected small saving from skipping a re-profile — negligible in this fake-env benchmark, but meaningful on a real device where `profileHardware()`'s real GPU cost dominates.
- No industry-standard equivalent exists to compare against (this is a novel decision layer, not a drop-in replacement for a common pattern) — the goal here is just confirming the package itself adds no meaningful overhead on top of the unavoidable real-device probing cost.
